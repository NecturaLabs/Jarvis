# Getting help

- **Something is broken or missing**: search the
  [open issues](https://github.com/NecturaLabs/jarvis/issues) first. If it is new, file a bug with the
  [bug form](https://github.com/NecturaLabs/jarvis/issues/new/choose), or start a
  [discussion](https://github.com/NecturaLabs/jarvis/discussions) if you are not sure it is a bug. Include the
  output of `jarvis --version` and `jarvis doctor`, your Omarchy and kernel versions, and the steps that show
  it. `jarvis logs` follows the live log. Logs and the audit log can contain what you and your PC said:
  redact anything you do not want public, and leave out Spotify tokens and recordings.
- **A question about using Jarvis**: the [README](README.md) covers install and the commands,
  [docs/configuration.md](docs/configuration.md) every setting and [docs/models.md](docs/models.md) the model,
  voices and wake word. If those do not answer it, ask in
  [Discussions](https://github.com/NecturaLabs/jarvis/discussions) (Q&A), where the answer helps the next
  person too. E-mail support@necturalabs.com only for something private.
- **A security problem**: never in a public issue. Follow [SECURITY.md](SECURITY.md).
- **Behaviour in project spaces**: see the [code of conduct](CODE_OF_CONDUCT.md).
- **An accessibility barrier**: see [ACCESSIBILITY.md](ACCESSIBILITY.md).

Jarvis has one maintainer, so replies come when there is time; see
[CONTRIBUTING.md](CONTRIBUTING.md#what-to-expect).
